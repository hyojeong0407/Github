# Requirements

## 1. 프로젝트 개요

### 1.1 목적

가정에서 데스크톱 PC 또는 노트북을 사용하는 사용자가 자신의 PC 사용 환경과 장비 소비전력을 입력하면, 예상 전력 사용량과 전기요금을 계산하고 대시보드에서 분석할 수 있도록 한다.

본 시스템은 단순 계산기를 넘어 다음 정보를 제공한다.

- PC와 모니터의 예상 전력 사용량
- 일간·주간·월간 예상 전기요금
- 기간별 전력 사용량 추이
- 사용시간 변경에 따른 비용 비교
- 전력 절감 가능 금액
- 사용자 입력과 계산 결과에 근거한 절전 추천

### 1.2 개발 범위

현재 단계에서는 코드를 작성하지 않고, 구현에 필요한 요구사항과 검증 기준을 확정한다. 구현은 본 문서에 대한 검토와 승인 이후 진행한다.

개발 프로세스는 다음 순서를 따른다.

1. Requirements 작성
2. Specification 작성 및 구체화
3. Specification Validation
4. Implementation Plan 작성
5. Implementation
6. Test
7. Review

### 1.3 주요 사용자

가정에서 데스크톱 PC 또는 노트북을 사용하는 일반 사용자이다. 사용자는 자신의 PC가 소비하는 전력과 월간 예상 전기요금을 확인하고, 사용량을 줄였을 때 예상되는 비용 절감 효과를 비교할 수 있어야 한다.

## 2. 사용자 시나리오

### US-001 기본 사용량 분석

사용자로서 PC 소비전력, 하루 평균 사용시간, 월간 사용일수, 모니터 정보를 입력하고 PC 사용에 따른 월간 전력 사용량과 예상 전기요금을 확인하고 싶다.

### US-002 장비별 소비전력 확인

사용자로서 PC 본체와 각 모니터의 소비전력을 비교하여 어떤 장비가 전체 사용량에 크게 기여하는지 확인하고 싶다.

### US-003 기간별 추이 확인

사용자로서 일·주·월 단위의 전력 사용량 추이를 확인하고 분석 기간을 변경하고 싶다.

### US-004 절감 효과 시뮬레이션

사용자로서 하루 평균 사용시간을 변경해 보면서 전력 사용량, 예상 전기요금, 절감 전력량, 예상 절감액, 절감률의 변화를 비교하고 싶다.

### US-005 절전 방법 추천

사용자로서 내 입력값과 실제 계산 결과를 바탕으로 적용 가능한 절전 방법을 추천받고 싶다.

## 3. 기능 요구사항

각 기능 요구사항은 고유한 FR ID를 가진다. 모든 수치 결과에는 적절한 단위를 표시해야 한다.

### FR-001 PC 정보 입력

시스템은 사용자가 PC 소비전력(W), 하루 평균 사용시간(시간), 월간 사용일수(일)를 입력할 수 있도록 해야 한다.

#### 수용 기준

- Given 사용자가 입력 화면을 열었을 때, When PC 정보 입력 영역을 확인하면, Then PC 소비전력·하루 평균 사용시간·월간 사용일수 입력 필드가 표시되어야 한다.
- Given 사용자가 유효한 값을 입력했을 때, When 분석을 실행하면, Then 입력값이 계산에 반영되어야 한다.

### FR-002 모니터 정보 입력

시스템은 사용자가 모니터 소비전력(W)과 모니터 개수를 입력할 수 있도록 해야 한다. 모니터가 여러 대인 경우 개별 모니터 정보를 구분할 수 있어야 한다.

#### 수용 기준

- Given 사용자가 모니터 정보를 입력할 때, When 모니터 소비전력과 개수를 입력하면, Then 전체 소비전력 계산에 모니터 정보가 반영되어야 한다.
- Given 모니터 개수가 증가할 때, When 모니터 소비전력이 동일하면, Then 모니터 전체 소비전력은 개수에 비례하여 증가해야 한다.

### FR-003 선택 정보 입력

시스템은 필요에 따라 사용 시작 시간, 사용 종료 시간, PC 사용 목적(게임·업무·영상 시청 등)을 입력할 수 있도록 해야 한다. 선택 입력값이 없는 경우에도 필수 입력만으로 기본 분석을 수행할 수 있어야 한다.

### FR-004 전체 소비전력 계산

시스템은 PC와 모니터의 소비전력을 합산하여 전체 소비전력을 계산해야 한다.

`전체 소비전력(W) = PC 소비전력(W) + 모니터 소비전력(W) × 모니터 개수`

#### 수용 기준

- Given PC 소비전력, 모니터 소비전력, 모니터 개수가 유효할 때, When 계산을 실행하면, Then 위 공식에 따른 전체 소비전력을 W 단위로 표시해야 한다.

### FR-005 일일 전력 사용량 계산

시스템은 전체 소비전력과 하루 평균 사용시간을 기반으로 일일 전력 사용량을 계산해야 한다.

`일일 전력 사용량(kWh) = 전체 소비전력(W) ÷ 1000 × 하루 사용시간(시간)`

#### 수용 기준

- Given 전체 소비전력과 하루 사용시간이 유효할 때, When 계산을 실행하면, Then 일일 전력 사용량을 kWh 단위로 표시해야 한다.

### FR-006 월간 전력 사용량 계산

시스템은 일일 전력 사용량과 월간 사용일수를 기반으로 월간 예상 전력 사용량을 계산해야 한다.

`월간 전력 사용량(kWh) = 일일 전력 사용량(kWh) × 월간 사용일수(일)`

#### 수용 기준

- Given 일일 전력 사용량과 월간 사용일수가 유효할 때, When 계산을 실행하면, Then 월간 예상 전력 사용량을 kWh 단위로 표시해야 한다.

### FR-007 예상 전기요금 계산

시스템은 월간 전력 사용량을 전기요금 계산 모듈에 전달하여 월간 예상 전기요금을 계산해야 한다.

전기요금 계산은 사용량, 누진구간, 기본요금, 전력량요금 및 필요한 기타 항목을 고려할 수 있어야 한다. 최신 대한민국 주택용 전력 요금 기준을 검증하기 전에는 임의의 단가를 사실로 사용해서는 안 된다.

#### 수용 기준

- Given 월간 전력 사용량과 유효한 요금 기준이 있을 때, When 요금 계산을 실행하면, Then 예상 전기요금을 원 단위로 표시해야 한다.
- Given 요금 기준이 변경될 때, When 계산 모듈의 설정 또는 요금 데이터만 변경하면, Then 다른 기능의 수정 없이 새로운 기준으로 계산할 수 있어야 한다.
- Given 요금 기준이 검증되지 않았을 때, When 사용자에게 결과를 표시하면, Then 해당 결과가 예시 또는 추정값임을 명확히 표시해야 한다.

### FR-008 KPI 표시

시스템은 대시보드 상단에 다음 KPI를 카드 형태로 표시해야 한다.

- 월간 예상 전력 사용량(kWh)
- 월간 예상 전기요금(원)
- 하루 평균 사용시간(시간)
- 예상 절감 가능 금액(원)

#### 수용 기준

- Given 유효한 입력값으로 분석이 완료되었을 때, When 대시보드를 표시하면, Then 네 가지 KPI와 각 단위가 표시되어야 한다.
- Given 계산 결과가 변경될 때, When 대시보드를 갱신하면, Then KPI 값도 최신 계산 결과와 일치해야 한다.

### FR-009 전력 사용량 추이 표시

시스템은 일·주·월 단위의 전력 사용량을 그래프로 표시해야 하며, 사용자가 분석 기간을 변경하면 그래프도 해당 기간에 맞게 변경해야 한다. 기본 시각화는 Line Chart를 우선 검토한다.

#### 수용 기준

- Given 기간별 데이터가 있을 때, When 사용자가 일·주·월 단위를 선택하면, Then 선택한 단위의 전력 사용량 추이가 표시되어야 한다.
- Given 사용자가 분석 기간을 변경할 때, When 변경을 적용하면, Then 그래프의 데이터 범위가 변경된 기간과 일치해야 한다.

### FR-010 장비별 소비전력 분석

시스템은 PC 본체, 모니터 1, 모니터 2 및 기타 장비의 소비전력을 비교하여 표시해야 한다. 장비 수가 가변적일 수 있으므로 실제 입력된 장비만 표시해야 한다. 기본 시각화는 Bar Chart 또는 동등하게 이해하기 쉬운 방법을 사용한다.

### FR-011 사용 패턴 분석

시스템은 입력된 선택 정보와 분석 데이터를 기반으로 다음 정보를 제공해야 한다.

- 가장 많이 사용하는 시간대(시간대 데이터가 입력 또는 수집된 경우)
- 하루 평균 사용시간
- 월간 예상 사용량
- 이전 기간 대비 사용량 변화(비교 데이터가 있는 경우)

비교 데이터나 시간대 데이터가 없는 경우 해당 항목은 미제공 사유를 표시해야 한다.

### FR-012 절감 시뮬레이션

시스템은 사용자가 변경한 하루 평균 사용시간을 기준으로 전력 사용량과 전기요금을 재계산하고 기존 조건과 비교해야 한다.

시뮬레이션 결과에는 다음 항목을 포함해야 한다.

- 기존 월간 전력 사용량
- 변경 월간 전력 사용량
- 절감 전력량
- 기존 예상 전기요금
- 변경 예상 전기요금
- 예상 절감 금액
- 절감률

#### 수용 기준

- Given 기존 사용시간과 변경 사용시간이 유효할 때, When 사용자가 시뮬레이션을 실행하면, Then 기존 조건과 변경 조건의 결과를 함께 표시해야 한다.
- Given 변경 사용시간이 기존 사용시간보다 적을 때, When 계산을 실행하면, Then 절감 전력량과 예상 절감 금액은 양수 또는 0으로 계산되어야 한다.
- Given 변경 사용시간이 기존 사용시간보다 많을 때, When 계산을 실행하면, Then 결과를 증가량으로 표시하고 절감으로 오해하지 않도록 구분해야 한다.

### FR-013 절감액 및 절감률 계산

시스템은 기존 조건과 변경 조건의 차이를 기반으로 절감액과 절감률을 계산해야 한다.

`절감 전력량 = 기존 월간 전력 사용량 - 변경 월간 전력 사용량`

`예상 절감 금액 = 기존 예상 전기요금 - 변경 예상 전기요금`

`절감률(%) = 예상 절감 금액 ÷ 기존 예상 전기요금 × 100`

기존 예상 전기요금이 0인 경우 절감률을 계산하지 않고 적절한 대체 표시를 제공해야 한다.

### FR-014 AI 절전 추천

시스템은 사용자의 입력값과 계산·분석 결과에 근거하여 전력 절감 방법을 추천해야 한다.

추천 예시는 다음과 같다.

- 하루 사용시간 줄이기
- 소비전력이 낮은 장비 사용
- 미사용 시 절전모드 사용
- 장시간 사용하지 않는 주변기기 전원 차단

추천은 실제 입력값 또는 계산 결과와 연결된 근거를 포함해야 하며, 근거 없는 임의의 정보나 계산 결과와 무관한 추천을 생성해서는 안 된다. AI 기능의 구체적인 구현 방식은 Design 단계에서 확정한다.

### FR-015 분석 기간 및 데이터 기준 표시

헤더에는 서비스명, 현재 분석 기간, 데이터 기준을 표시해야 한다. 데이터 기준에는 실제 측정값인지, 사용자 입력 기반 추정값인지, 예시 데이터인지 구분이 포함되어야 한다.

## 4. 비기능 요구사항

### NFR-001 모듈화

계산 로직, UI, 데이터 처리, 전기요금 계산, 분석, AI 추천 기능은 독립적인 모듈로 분리할 수 있어야 한다. 최소한 `input`, `power_calculator`, `electricity_bill`, `analyzer`, `recommendation`, `dashboard`, `tests` 영역을 분리하는 방향을 검토한다.

### NFR-002 유지보수성

전기요금 계산 기준이 변경되어도 전체 프로그램을 수정하지 않고 요금 계산 모듈 또는 외부 설정·데이터 구조를 변경할 수 있어야 한다.

### NFR-003 사용성

사용자가 별도의 설명 없이도 주요 전력 사용량과 요금 정보를 이해할 수 있도록 직관적인 입력 화면과 대시보드를 제공해야 한다.

### NFR-004 단위 명확성

모든 수치에는 W, kWh, 시간, 일, 원, % 등 적절한 단위를 표시해야 한다. 서로 다른 단위의 값이 혼동되지 않도록 입력 필드와 결과 영역에 단위를 함께 표시해야 한다.

### NFR-005 테스트 가능성

주요 계산 기능과 입력값 검증 기능은 UI와 독립적으로 단위 테스트할 수 있어야 한다. 요금 계산 기준이 바뀌어도 계산 모듈을 별도로 검증할 수 있어야 한다.

### NFR-006 계산 일관성

동일한 입력값과 동일한 요금 기준을 사용하면 화면, 시뮬레이션, 그래프에 표시되는 계산 결과가 일관되어야 한다.

### NFR-007 기술 선택 근거

Python, Streamlit, Pandas, Plotly 또는 Streamlit에서 지원하는 시각화 라이브러리와 Python 테스트 프레임워크를 우선 검토한다. 다른 기술을 선택하는 경우 요구사항 충족에 유리한 이유를 Specification Validation 또는 Design 문서에 기록해야 한다.

|---|---|---|---|---|
| PC 소비전력 | 필수 | W | PC 본체의 소비전력 | 0보다 큰 숫자 |
| 하루 평균 사용시간 | 필수 | 시간 | 하루 PC 사용시간 | 0 초과, 24 이하 |
| 월간 사용일수 | 필수 | 일 | 한 달 동안 PC를 사용하는 일수 | 0 초과, 31 이하 |
| 모니터 소비전력 | 필수 | W | 모니터 1대의 소비전력 | 0 이상 숫자, 정책 확정 필요 |
| 모니터 개수 | 필수 | 대 | 연결된 모니터 수 | 0 이상 정수 |
| 사용 시작 시간 | 선택 | 시각 | PC 사용 시작 시각 | 입력 시 유효한 시간 형식 |
| 사용 종료 시간 | 선택 | 시각 | PC 사용 종료 시각 | 입력 시 유효한 시간 형식 |
| PC 사용 목적 | 선택 | - | 게임·업무·영상 시청 등 | 허용 목록 또는 자유 입력 정책 확정 필요 |
| 기타 장비 | 선택 | W/대 | 기타 장비별 소비전력과 수량 | 입력 시 0 이상 숫자 |

## 6. 출력 데이터 명세

| 출력 항목 | 단위 | 설명 |
|---|---|---|
| 전체 소비전력 | W | PC와 모니터 소비전력의 합계 |
| 일일 전력 사용량 | kWh | 하루 기준 예상 사용량 |
| 월간 전력 사용량 | kWh | 월간 사용일수를 반영한 예상 사용량 |
| 월간 예상 전기요금 | 원 | 적용된 요금 기준에 따른 추정 요금 |
| 하루 평균 사용시간 | 시간 | 입력값 또는 분석값 |
| 기간별 전력 사용량 | kWh | 일·주·월 단위 추이 데이터 |
| 장비별 소비전력 | W | PC, 모니터 및 기타 장비별 값 |
| 절감 전력량 | kWh | 기존 조건과 변경 조건의 차이 |
| 예상 절감 금액 | 원 | 기존 요금과 변경 요금의 차이 |
| 절감률 | % | 기존 요금 대비 절감 비율 |
| 절전 추천 | - | 입력·계산 결과에 근거한 추천과 근거 |

모든 출력값은 실제 측정값, 사용자 입력 기반 추정값, 예시값 중 어떤 유형인지 구분해야 한다.

## 7. 계산 규칙

### 7.1 기본 전력 계산

`전체 소비전력(W) = PC 소비전력(W) + 모니터 소비전력(W) × 모니터 개수`

`일일 전력 사용량(kWh) = 전체 소비전력(W) ÷ 1000 × 하루 사용시간(시간)`

`월간 전력 사용량(kWh) = 일일 전력 사용량(kWh) × 월간 사용일수(일)`

기타 장비를 지원하는 경우 기타 장비의 소비전력을 전체 소비전력에 포함하는 규칙을 Design 단계에서 명확히 해야 한다.

### 7.2 절감 계산

`절감 전력량(kWh) = 기존 월간 전력 사용량 - 변경 월간 전력 사용량`

`예상 절감 금액(원) = 기존 예상 전기요금 - 변경 예상 전기요금`

`절감률(%) = 예상 절감 금액 ÷ 기존 예상 전기요금 × 100`

절감률의 분모가 0인 경우 0으로 임의 처리하지 않고 `계산 불가` 또는 동등한 안내를 표시한다.

### 7.3 반올림 및 표시

내부 계산 정밀도와 사용자 화면 표시 자릿수는 분리할 수 있어야 한다. 반올림 기준, 0에 가까운 값의 표시 방식, 원 단위 처리 방식은 Design 단계에서 확정한다.

## 8. 전기요금 계산 구조

전기요금 계산 로직은 독립 모듈로 분리한다. 요금 단가와 누진구간은 코드에 직접 하드코딩하지 않고 설정값 또는 데이터 구조로 관리해야 한다.

계산 구조는 최소한 다음 입력과 항목을 확장할 수 있어야 한다.

- 월간 사용량(kWh)
- 요금 적용 대상 및 주택용 여부
- 누진구간
- 기본요금
- 전력량요금
- 기타 필요한 요금 항목
- 요금 기준의 버전 또는 적용일

실제 대한민국 주택용 전력 요금 체계를 적용할 때는 최신 공식 자료를 별도로 검증하고 출처와 적용 기준일을 기록해야 한다. 검증 전에는 특정 단가를 확정값으로 표시하지 않는다.

## 9. 대시보드 화면 명세

### 9.1 헤더

서비스명, 현재 분석 기간, 데이터 기준을 표시한다.

### 9.2 KPI 영역

월간 예상 전력 사용량, 월간 예상 전기요금, 하루 평균 사용시간, 예상 절감 가능 금액을 카드 형태로 표시한다.

### 9.3 전력 사용량 추이 영역

일·주·월 단위 선택과 분석 기간 변경을 지원하고, 선택에 따라 전력 사용량 그래프를 갱신한다.

### 9.4 장비별 소비전력 영역

PC 본체, 모니터 1, 모니터 2, 기타 장비를 비교한다. 실제로 존재하지 않는 장비를 임의로 표시하지 않는다.

### 9.5 사용 패턴 분석 영역

가장 많이 사용하는 시간대, 하루 평균 사용시간, 월간 예상 사용량, 이전 기간 대비 사용량 변화를 표시한다. 근거 데이터가 없는 항목은 데이터 부족 상태를 명확히 표시한다.

### 9.6 절감 시뮬레이션 영역

사용자가 변경 사용시간을 입력하면 기존 조건과 변경 조건을 비교하여 전력량·요금·절감액·절감률을 표시한다.

### 9.7 AI 절전 추천 영역

추천 내용, 추천 근거가 된 입력·분석 데이터, 적용 시 기대되는 변화가 서로 연결되도록 표시한다. 검증되지 않은 확정적 절감액은 표시하지 않는다.

## 10. 입력값 검증 및 예외 처리

다음 입력은 오류로 처리하고 사용자가 이해하기 쉬운 메시지를 표시해야 한다.

## 12. 시스템 아키텍처 요구사항

시스템은 다음 계층의 책임을 분리하는 방향으로 설계해야 한다.

`Input Layer → Data Processing Layer → Calculation Layer → Analysis Layer → AI Recommendation Layer → Dashboard UI`

각 계층은 다음 책임을 가진다.

- Input Layer: 사용자 입력 수집 및 기본 형식 검증
- Data Processing Layer: 입력 정규화, 데이터 변환, 기간별 데이터 준비
- Calculation Layer: 전력량, 절감량, 절감률 계산
- Analysis Layer: 기간별 추이와 사용 패턴 분석
- AI Recommendation Layer: 분석 결과에 근거한 절전 추천 생성
- Dashboard UI: 입력 화면, KPI, 그래프, 시뮬레이션, 추천 결과 표시

계산 로직과 UI를 분리해야 하며, 전기요금 계산 모듈은 독립적으로 교체·검증할 수 있어야 한다.

## 13. Specification Validation에서 확인할 모호하거나 부족한 부분

다음 항목은 구현 전에 결정하거나 별도 검증해야 한다.

1. 실제 전기요금 적용 범위: PC 사용으로 증가한 요금만 계산할지, 가정 전체 전력 사용량과 합산할지 결정해야 한다.
2. 최신 요금 기준: 대한민국 주택용 전력의 적용 제도, 누진구간, 기본요금, 부가 항목, 기준일과 공식 출처를 확정해야 한다.
3. 월간 사용일수와 달력: 월을 항상 31일로 볼지, 사용자가 입력한 사용일수를 그대로 사용할지 결정해야 한다.
4. 모니터 소비전력 입력 규칙: 모니터별 소비전력을 각각 받을지, 동일한 소비전력을 여러 대에 적용할지 결정해야 한다.
5. 기타 장비: 초기 범위에 포함할 장비 종류와 전체 전력 계산 포함 여부를 확정해야 한다.
6. 기간별 추이 데이터: 실제 측정 데이터를 수집할지, 사용자 입력 기반 추정 데이터를 시간 단위로 분배할지 결정해야 한다.
7. 이전 기간 비교: 이전 기간 데이터의 저장·조회 방식과 비교 기준을 결정해야 한다.
8. 시작·종료 시간: 자정을 넘기는 사용 시간과 휴식·절전 시간을 어떻게 처리할지 결정해야 한다.
9. 사용 목적: 자유 입력인지 미리 정의된 선택지인지 결정해야 한다.
10. AI 추천: 외부 AI 모델을 사용할지, 규칙 기반 추천으로 시작할지, 추천 생성 실패 시 대체 동작을 결정해야 한다.
11. 절감률 표시: 요금이 증가하는 경우 음수 절감률을 표시할지, 절감이 아닌 증가로 별도 표시할지 결정해야 한다.
12. 반올림: 전력량과 요금의 내부 정밀도 및 화면 표시 자릿수를 확정해야 한다.
13. 데이터 저장: 세션 동안만 보관할지, 파일 또는 데이터베이스에 저장할지 결정해야 한다.
14. 인증과 개인정보: 사용자 계정, 개인정보, 입력 데이터의 보존 범위를 결정해야 한다.

## 14. 개선이 필요한 요구사항

- `AI 절전 추천`은 AI라는 명칭만으로는 구현·검증 기준이 부족하므로, 추천 입력·출력 형식, 근거 표시, 추천 실패 시 동작, 외부 모델 사용 여부를 추가로 정의해야 한다.
- `기간별 전력 사용량 추이`는 현재 실제 측정 데이터의 수집 방법과 추정 데이터 생성 규칙이 정의되지 않았으므로 데이터 출처를 확정해야 한다.
- `월간 예상 전기요금`은 가정 전체 사용량을 반영하는지 PC 관련 증가분만 계산하는지에 따라 결과가 크게 달라지므로 계산 범위를 확정해야 한다.
- `모니터 정보`는 단일 소비전력×개수 방식과 장비별 입력 방식이 혼재할 수 있으므로 초기 버전의 입력 모델을 하나로 확정해야 한다.
- `사용 패턴 분석`에서 가장 많이 사용하는 시간대와 이전 기간 비교는 현재 입력 항목만으로 항상 산출할 수 없으므로 필요한 데이터 확보 방법을 추가해야 한다.
- `기타 장비`가 화면 명세에는 있으나 입력 명세와 기본 계산식에는 선택적으로만 등장하므로 초기 범위 포함 여부를 확정해야 한다.
- `절전 추천`의 절감 금액은 추천 효과를 정량화할 수 있는 근거가 있을 때만 표시하고, 그렇지 않으면 정성적 추천으로 표시해야 한다.
- 전기요금 최신 자료를 외부에서 적용할 때는 출처, 조회일, 적용 기간을 함께 기록해야 한다.

## 15. 승인된 정책 결정 및 범위 제한

- **계산 범위**: 가정 전체 사용량이 아니라 PC와 모니터 사용으로 증가한 전력량만 계산한다. PC 사용분 kWh를 독립 사용량으로 요금표에 적용하며 결과는 `PC 사용분 기준 예상 증가액`이고 실제 가정 청구액이 아님을 표시한다.
- **출처 우선순위**: `measured` 실측값 > `manufacturer_estimate` 제조사/사용자 제공 추정값 > `user_estimate` 사용자 입력 추정값 > `example` 예시값. 계산 결과에는 source/status를 보존하고 기본값은 `user_estimate`로 유지한다.
- **입력 범위**: PC·모니터 전력, 하루 사용시간, 월간 사용일수, 모니터 수가 필수이며 시작·종료 시간과 목적은 선택이다. 기타 장비는 제외하고 실제 측정값은 임의 생성하지 않는다.
- **요금과 반올림**: `TariffConfig`의 source/version/effective period/status를 표시한다. 현재 10원/kWh는 공식 단가가 아닌 `example` 설정이다. 내부 원시값을 유지하고 kWh 2자리, W 필요 시 2자리, 시간 1자리, 금액 정수 원, 절감률 1자리로 표시한다. 0원 분모는 계산 불가, 사용량 증가는 증가로 표시한다.
- **보류**: 공식 최신 단가 검증과 실측 CSV 수집·영속 저장은 후속 범위이며 확장 지점을 문서화한다.



원본 FR-001~FR-015, NFR-001~NFR-007 및 US/TC ID의 범위와 의미는 변경하지 않는다. 사용자가 승인한 원본 Spec 범위 밖 확장으로 다음 기능을 추가한다.

- **FR-016-A 사용시간 프리셋**: 기존 하루 사용시간을 기준으로 1시간 줄이기, 2시간 줄이기, 절반으로 줄이기를 제공하고 기존 `simulation.simulate` 경로로 재계산한다. 프리셋 결과는 0시간 미만이 되지 않는다.
- **FR-016-B 새싹형 소비 단계**: 월간 예상 kWh를 명시적 설정 경계값으로 분류해 🌰 씨앗, 🌱 새싹, 🌿 잎새, 🌳 나무, 🌲 큰 나무와 의미·다음 단계 안내를 표시한다. 큰 나무는 좋은 등급이 아니라 사용량이 많은 단계임을 보조 설명한다.
- **FR-016-C 추천 우선순위**: 기존 근거 기반 추천을 유지하고 입력·계산 결과에 연결된 priority/rank로 정렬한다. 근거 없는 절감액은 추가하지 않는다.

이 확장 기능은 사용자가 승인했으며, 기존 요구사항의 계산·표시 계약을 대체하지 않는다.

본 시스템은 사용자가 입력한 PC·모니터 소비전력과 사용 패턴을 기반으로 전체 소비전력, 일일 전력 사용량, 월간 전력 사용량, 예상 전기요금을 계산하고 웹 대시보드로 시각화한다. 사용자는 KPI, 기간별 추이, 장비별 비교, 사용 패턴, 절감 시뮬레이션, 절전 추천을 확인할 수 있다.

모든 계산은 검증 가능한 공식과 독립 모듈을 통해 수행하며, 전기요금 기준은 외부 설정 또는 데이터 구조로 관리한다. 입력값 오류와 데이터 부족 상태를 명확히 표시하고, 실제값·추정값·예시값을 구분한다. 구현 전 위의 모호한 항목을 확정하고, 본 문서의 Requirement ID와 Test Case ID를 기준으로 Specification Validation 및 이후 구현·테스트·리뷰를 진행한다.

### 구현 전 승인 조건

- 모든 필수 입력과 유효 범위가 확정되어야 한다.
- 전기요금 계산 범위와 최신 공식 요금 기준이 검증되어야 한다.
- 추이·이전 기간 비교에 사용할 데이터 출처가 확정되어야 한다.
- AI 추천의 구현 방식과 근거 표시 규칙이 확정되어야 한다.
- Design 및 Tasks 단계로 진행하기 전에 본 Requirements 문서를 검토·승인해야 한다.
